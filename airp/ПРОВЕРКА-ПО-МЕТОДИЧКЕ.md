## ЛР2. Сокеты — вариант 2 (два клиента-потока, один счёт)

| Требование | Где | Статус |
|---|---|---|
| Поток-сервер `Account extends Thread`, `ServerSocket(3001)`, `accept()` | `serv.java` | ✅ |
| Поток-клиент `clientThread extends Thread`, `new Socket(host, 3001)`, чтение `DataInputStream.readLine()` | `serv.java` | ✅ |
| Сервер отдаёт `"Account:" + сумма`, `PrintStream`, `flush`, `close` | `Account.run` | ✅ |
| Начальный счёт 200, `static int amount` | `Account` | ✅ |
| Визуальный интерфейс: запуск клиента **по кнопке**, счёт в текстовом поле | кнопки + `accountField` | ✅ |
| Вариант 2: клиент 1 добавляет и снимает, клиент 2 **только снимает** | три кнопки: «К1 добавить», «К1 снять», «К2 снять» | ✅ |
| Каждому клиенту — свой поток | новый `clientThread` на каждое нажатие | ✅ |
| Адрес сервера задаётся (не только 127.0.0.1) | аргумент `java -jar serv.jar <IP>` | ✅ (для «трёх компьютеров» из чата) |

Отличия от «заготовки» (намеренные): знак операции задаёт клиент (`ADD`/`WITHDRAW`), а не случайный `Math.random() > 0.5`, иначе нельзя выполнить требование «клиент 2 только снимает»; старые `handleEvent`/`mouseDown`/`resize`/`show` заменены на `ActionListener`, `setSize`, `setVisible` (старые методы удалены/устарели в современных JDK).

Замечание: `DataInputStream.readLine()` помечен как deprecated — взят из методички, работает.
