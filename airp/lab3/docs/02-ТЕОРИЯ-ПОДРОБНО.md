# АИРП-3. Теория подробно

## 1. Клиент и сервер, HTTP

**Клиент** (браузер или программа) отправляет **запрос**, **сервер** возвращает **ответ**. Язык общения – протокол **HTTP**.

**Запрос** содержит: метод (`GET`, `POST`), адрес (URL), заголовки, иногда тело. **Ответ**: код состояния (`200 OK`, `404 Not Found`, `500 Internal Server Error`), заголовки (`Content-Type`) и тело (HTML, картинка и т. д.).

### GET и POST

| | GET | POST |
|---|---|---|
| Где данные формы | **в адресе**: `MyServlet?txt=привет` | в теле запроса |
| Видно в адресной строке | да | нет |
| Применение | получение данных, поиск | отправка больших или секретных данных |

В методичке: «в методе Get данные формы передаются одним сообщением вместе со служебной информацией (заголовком); в методе Post данные передаются отдельно от заголовка (в теле)». Наш словарь использует `Get`.

### Кодирование адреса

Русские буквы в адресе передаются в виде `%D0%BF...` (URL-кодирование UTF-8): так в адресной строке `привет` превращается в `%D0%BF%D1%80%D0%B8%D0%B2%D0%B5%D1%82`. Клиент делает это методом `URLEncoder.encode(слово, "UTF-8")`.

## 2. Сервлет

**Сервлет** – класс Java, выполняющийся **на стороне сервера** и обрабатывающий запросы клиентов. Он живёт внутри **контейнера сервлетов** (у нас Apache Tomcat), который принимает HTTP-запросы и передаёт их сервлетам.

Жизненный цикл:

1. `init()` – один раз при создании (мы создаём базу данных).
2. На каждый запрос контейнер вызывает `service()`, который направляет в `doGet()` или `doPost()` (по методу запроса).
3. `destroy()` – при остановке.

Основные объекты:

| Объект | Назначение | Важные методы |
|---|---|---|
| `HttpServletRequest request` | запрос клиента | `getParameter("txt")` – значение поля формы |
| `HttpServletResponse response` | ответ клиенту | `setContentType("text/html;charset=UTF-8")`, `getWriter()`, `getOutputStream()` |

В методичке `doGet` и `doPost` **перенаправлены на один метод** `processRequest(request, response)`, где собрана вся обработка.

### Как вернуть результат клиенту

- **Текст/HTML:** `PrintWriter out = response.getWriter(); out.println("<html>...</html>");`
- **Файл (рисунок, документ):** задать **тип содержимого** (`image/png`), затем записать байты файла в `response.getOutputStream()`. Браузер по типу решает, как показать: рисунок отображается сам.

## 3. Страница и форма

```html
<form name="frm" method="Get" action="MyServlet">
   <Input type="Text" name="txt" value=""/>
   <Input type="submit" value="Перевести"/>
</form>
```

- `action="MyServlet"` – **какой сервлет вызвать** (адрес, по которому он зарегистрирован в `web.xml`);
- `method="Get"` – данные пойдут в адресе;
- `name="txt"` – имя поля; на сервере читается `request.getParameter("txt")`;
- `type="submit"` – кнопка отправки.

Строка `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">` нужна, чтобы браузер правильно показывал русский текст.

## 4. web.xml (дескриптор развёртывания)

Файл `WEB-INF/web.xml` объясняет контейнеру, какие сервлеты есть и по каким адресам их вызывать.

| Тег | Что значит |
|---|---|
| `<servlet>` + `<servlet-name>` + `<servlet-class>` | **объявление**: имя сервлета и его класс |
| `<servlet-mapping>` + `<url-pattern>` | **привязка к адресу**: `/MyServlet` → сервлет `MyServlet` |
| `<welcome-file-list>` | **стартовая страница** приложения (`dictionary.html`) |
| `<session-config>` | настройки сессии (таймаут 30 минут) |

Цепочка: адрес `/lab_servlet/MyServlet` → контекст `lab_servlet` (имя WAR) → `url-pattern /MyServlet` → `servlet-name MyServlet` → `servlet-class MyServlet` → вызов метода сервлета.

## 5. WAR, Maven, Tomcat

- **WAR** (Web ARchive) – архив веб-приложения: страницы, классы, библиотеки, `web.xml`.
- **Maven** – система сборки: читает `pom.xml`, скачивает библиотеки, компилирует, собирает WAR (`mvn package`).
- **Tomcat** – сервер: распаковывает WAR из `webapps/` и запускает приложение. Имя файла (`lab_servlet.war`) становится первой частью адреса (`/lab_servlet/`).

Структура проекта по методичке (NetBeans, шаблон Java Web): страницы – `WEB-INF` и корень; классы – «Пакеты исходных файлов»; библиотеки – «Библиотеки»; конфигурация – `web.xml`. У нас та же структура в формате Maven (`src/main/java`, `src/main/webapp`).

## 6. База данных переводов

Задание: «использовать базу данных, содержащую переводы слов». Используется встроенная база **H2** (работает в памяти приложения, ничего устанавливать не нужно). Обращение – через **JDBC** (стандартный способ Java работать с БД):

1. `DriverManager.getConnection("jdbc:h2:mem:dictionary;DB_CLOSE_DELAY=-1")` – соединение;
2. `CREATE TABLE words (rus VARCHAR(50), eng VARCHAR(50))` – таблица из двух столбцов;
3. `INSERT INTO words VALUES ('привет', 'hello'), ...` – данные;
4. `SELECT eng FROM words WHERE rus = ?` – запрос; `?` заменяется значением через `PreparedStatement.setString` (**защита от SQL-инъекций**: слово не вставляется в текст запроса).

**Обратный перевод** – тот же запрос, но столбцы меняются местами: `SELECT rus FROM words WHERE eng = ?`.

## 7. Клиент в отдельном проекте

Задание: «использовать для клиента и сервера два разных проекта: вызвать сервлет из клиентского обычного Java-приложения, используя URL». Клиент `ApacheClient` использует библиотеку **Apache HttpClient**:

1. `HttpClients.createDefault()` – создать клиента;
2. `new HttpGet(url + "?txt=" + URLEncoder.encode(слово, "UTF-8"))` – запрос GET с параметром;
3. `client.execute(request)` – отправить;
4. `EntityUtils.toString(response.getEntity(), "UTF-8")` – прочитать тело ответа (HTML);
5. выделить из HTML текст между `<h2>` и `</h2>` и показать в окне Swing.

Так клиент и сервер – разные программы, общаются только по HTTP.

## 8. Вариант 2: сервлет с рисунком

`ImageServlet`: берёт файл `/images/picture.png` из приложения (`getServletContext().getResourceAsStream`), ставит тип `image/png`, копирует байты в ответ порциями по 4096 байт (**буфер**) и закрывает потоки. Браузер получает ответ с типом `image/png` и **сам отображает** рисунок.
