## Контрольные вопросы из методички

### 1. Что такое URL?
**URL (Uniform Resource Locator)** — «единый указатель ресурса»: строка, которая однозначно говорит, **где** лежит ресурс и **как** до него добраться.

```
https://example.com:8080/docs/page.html?x=1#top
└─┬──┘   └────┬────┘└┬─┘└──────┬──────┘└──┬─┘└─┬─┘
протокол    хост   порт     путь       запрос  якорь
```

- Протокол: `http`, `https`, `ftp`, `file`.
- В лабе используется **`file:`** — `file.toURI().toURL()` даёт `file:/E:/.../medicines.txt`.
- Класс `java.net.URL` хранит адрес, `url.openConnection()` возвращает `URLConnection`, а `getInputStream()` — поток байтов ресурса. Для `file:` и для `http:` код одинаковый, поэтому программу легко переделать на настоящий сайт.

### 2. Как программно получить список всех файлов в папке?
```java
File dir = new File("source_html");
File[] files = dir.listFiles();          // null, если папки нет!
```
В методичке: `new ArrayList<>(Arrays.asList(new File("c:/work/source_html").listFiles()))`.
В варианте 2 список лекарств лежит в `medicines.txt`, а `source_html` содержит html-описания; имя файла = `<название лекарства>.html`, поэтому найденный файл строится как `new File("source_html", bestName + ".html")`.
Альтернативы: `dir.list()` (только имена), `Files.list(Path)`, `Files.walk(Path)` (рекурсивно).

### 3. Как программно запустить браузер и открыть html-файл?
```java
Desktop.getDesktop().browse(file.getAbsoluteFile().toURI());
```
`java.awt.Desktop` обращается к браузеру по умолчанию. `browse` принимает **URI**, а не путь, поэтому `File → toURI()`. Старый способ — `Runtime.getRuntime().exec("cmd /c start file.html")`.

### 4. Объясните использование потоковых классов в вашем приложении.
Чтение файла идёт цепочкой «декораторов»:

```
файл → URLConnection.getInputStream()   байты
     → InputStreamReader(…, "UTF-8")     байты → символы
     → BufferedReader                    символы → строки (readLine)
```
- `InputStream` читает **байты**; `InputStreamReader` превращает их в символы с учётом кодировки (UTF-8, иначе русский текст «поплывёт»);
- `BufferedReader` накапливает данные в **буфере** и даёт метод `readLine()` — быстрее, чем читать по одному символу;
- `try (...)` закрывает потоки автоматически.

## Вопросы из чата преподавателя

### Назначения буфера (3 штуки — выучить)
1. **Выравнивание скорости** между медленным диском и быстрой оперативной памятью.
2. **Асинхронный ввод-вывод** — пока процессор занят, данные копятся/выгружаются в буфер.
3. **Кэширование данных** — повторное чтение берётся из буфера, а не с диска.

В лабе: `BufferedReader` — буфер между файлом и программой.

### Чем отличаются массив, `ArrayList` и `List`?
| | Что это |
|---|---|
| **Массив** `String[]` | встроенная структура, **размер фиксирован** при создании |
| **`ArrayList<T>`** | класс-коллекция на основе массива, **размер растёт сам**, хранит только объекты |
| **`List<T>`** | **интерфейс** (контракт: `add`, `get`, `size`…); `ArrayList` и `LinkedList` его реализуют |

«Термин list взять из Пролога» — список как упорядоченная последовательность элементов переменной длины. В коде: `ArrayList<String> lines` (список строк файла) и `String[] keywords` (ключевые слова после `split`).

### Куча, стек, кэш
- **Стек** — память потока: локальные переменные и вызовы методов (LIFO), быстро освобождается при выходе из метода.
- **Куча (heap)** — память для объектов (`new`), управляется сборщиком мусора, общая для потоков.
- **Кэш** — быстрая память между процессором и ОЗУ (L1/L2/L3), хранит недавно использованные данные.

В лабе: `keywords`, `bestCount` — локальные (стек); `ArrayList`, строки, окно — объекты в куче.

### Что такое «ListEnable»/«листэнэбл»
Скорее всего имелся в виду **Listener** (слушатель событий): `ActionListener` и метод `actionPerformed` — как программа реагирует на нажатие кнопки. Подробнее — в `ТЕОРИЯ_ИЗ_ЧАТА_АИРП.md`.

## Вероятные вопросы на защите ЛР1

| Вопрос | Ответ коротко |
|---|---|
| Как программа ищет лекарство? | Разбивает ввод по запятым, для каждой строки `medicines.txt` считает, сколько ключевых слов есть в симптомах, выбирает максимум |
| Что если ничего не совпало? | `bestName == null` → «Лекарство не найдено» |
| Зачем `toLowerCase()`? | Чтобы регистр не влиял на сравнение |
| Зачем `trim()`? | Убрать пробелы после запятых |
| Почему `AWT`, а не Swing? | Так в «заготовке» методички |
| Зачем `setLayout(null)`? | Ручная расстановка `setBounds` — как в методичке |
| Что делает `System.exit(0)`? | Завершает JVM; вызывается кнопкой Exit и закрытием окна |
| Что делает `split("\\|")`? | Делит строку по символу `|` (в регулярках `|` экранируется) |
