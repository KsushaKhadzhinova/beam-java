# АИРП, лабораторная работа 2. Mac: что установить, как настроить и что сказать

Mac в этой работе – **клиентский компьютер**. Сервер работает на ноутбуке с Windows, Mac подключается к нему по Wi-Fi и показывает окно «Счёт (клиент, …)». На Mac ничего компилировать не нужно: достаточно Java и готового файла `serv.jar`.

## 1. Что установить на Mac (один раз)

| Что | Как | Проверка |
|---|---|---|
| **Java (JDK 11 или новее, лучше 17)** | Вариант А, если есть Homebrew: `brew install --cask temurin@17`. Вариант Б: скачать установщик Temurin 17 для macOS (файл `.pkg`, выбрать свою архитектуру: Apple Silicon = aarch64, Intel = x64) на сайте adoptium.net и пройти установку | в Терминале: `java -version` – должна появиться строка `openjdk version "17..."` |
| **Файлы лабораторной** | `git clone https://github.com/KsushaKhadzhinova/beam-java.git` (если нет git, Mac сам предложит установить Command Line Tools – согласиться) или скопировать папку `airp/lab2` флешкой/AirDrop | в папке есть `serv.jar` и `2-start-client.sh` |

Терминал: Launchpad → «Другие» → «Терминал» (или Spotlight: `Cmd + Пробел`, ввести «Терминал»).

Если после установки Java команда `java` не найдена – закройте окно Терминала и откройте новое.

## 2. Как настроить сеть

1. **Оба ноутбука должны быть в одной Wi-Fi сети** (или Mac подключён к точке доступа, которую раздаёт Windows-ноутбук). Сеть гостевого Wi-Fi с «изоляцией клиентов» не подойдёт – устройства в ней не видят друг друга; тогда используйте раздачу интернета с телефона или точку доступа с ноутбука.
2. **На Windows-ноутбуке (сервер)** один раз откройте порт 3001: правой кнопкой по `ADMIN-open-port-3001.bat` → «Запуск от имени администратора». Скрипт создаёт правило брандмауэра, разрешающее входящие подключения на порт 3001.
3. **Узнать IP сервера.** На Windows запустите `show-ip.bat` (или в PowerShell `ipconfig`) и найдите адрес Wi-Fi адаптера, например `192.168.0.5`. Если сервер запущен, этот же адрес в заголовке окна: «Счёт (сервер, IP: 192.168.0.5)».
4. **Проверить, что Mac видит сервер** (сервер должен быть уже запущен). В Терминале:

```bash
nc -vz 192.168.0.5 3001
```

Ответ `Connection to 192.168.0.5 port 3001 [tcp/*] succeeded!` – всё в порядке. Если `timed out` – проверьте шаги 1–3 (чаще всего не открыт порт или разные Wi-Fi сети).

## 3. Запуск клиента на Mac

В Терминале перейдите в папку лабораторной и запустите клиент, указав IP сервера:

```bash
cd путь/к/airp/lab2
java -jar serv.jar 192.168.0.5
```

или через готовый скрипт (он сам спросит IP, если не указан):

```bash
sh 2-start-client.sh 192.168.0.5
```

Откроется окно «Счёт (клиент, сервер: 192.168.0.5)». Кнопки «Клиент 1: добавить», «Клиент 1: снять», «Клиент 2: снять» отправляют запросы на сервер. На сервере в журнале появится запись вида `[сервер] ADD от <IP Mac>, счёт: ...` – по IP видно, что запрос пришёл именно с Mac.

Если macOS не даёт запустить `.sh` или `.jar` из-за защиты «файл из интернета»: запуск через `java -jar ...` в Терминале её не затрагивает; для скрипта используйте `sh 2-start-client.sh ...` (с явным `sh`).

Если при первом запуске macOS спросит «Разрешить входящие подключения для java?» – для клиента это не требуется, можно нажать «Запретить»; клиент сам подключается наружу.

## 4. Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| В окне «нет связи с сервером …» | сервер не запущен, не тот IP или закрыт порт | запустить сервер, проверить IP (`show-ip.bat`), выполнить шаг 2 из раздела 2, повторить `nc -vz` |
| `java: command not found` | Java не установлена или Терминал открыт до установки | установить Java, открыть Терминал заново |
| `UnsupportedClassVersionError` | Java старше 11 | поставить Temurin 17 |
| Окно не открывается, ошибка про `DISPLAY`/`headless` | запуск по SSH без графики | запускать на самом Mac, в обычном Терминале |
| Тот же IP, но не подключается | IP сервера изменился (другая сеть/DHCP) | заново узнать IP и перезапустить клиент с новым адресом |

## 5. Что сказать на защите

Короткая версия (30 секунд):

> «Сервер – это программа на Windows-ноутбуке: он открывает серверный сокет на порту 3001 и ждёт подключений. Каждый клиент – отдельный поток, который открывает сокет к IP сервера, отправляет команду ADD или WITHDRAW, получает ответ со счётом и закрывается. Здесь клиентом выступает Mac: тот же `serv.jar`, запущенный командой `java -jar serv.jar <IP сервера>`. Java одинаково работает на Windows, macOS и Linux, поэтому один и тот же архив запускается на всех».

Порядок показа (3–4 минуты):

1. На Windows запустить сервер (`1-start-server.bat`) – показать окно, в заголовке IP.
2. На Mac в Терминале показать `java -version` и `nc -vz <IP> 3001` – сеть работает.
3. На Mac запустить `java -jar serv.jar <IP>`, нажать «Клиент 1: добавить».
4. Показать на сервере строку журнала с IP Mac – запрос действительно пришёл по сети.
5. Нажать «Клиент 1: снять» и «Клиент 2: снять» – показать, что сервер обрабатывает запросы по очереди и счёт общий.

Вопросы, которые могут задать, и ответы:

| Вопрос | Ответ |
|---|---|
| Почему один и тот же jar работает на Mac и Windows? | Java-код компилируется в байт-код, который исполняет виртуальная машина (JVM); под каждую ОС своя JVM, а байт-код один |
| Зачем порт 3001 и что такое сокет? | Порт – номер «двери» программы на компьютере; сокет – конец сетевого соединения «IP + порт» |
| Почему на Windows пришлось открывать порт? | Брандмауэр по умолчанию блокирует входящие подключения; клиент сам подключается наружу, поэтому на Mac правила не нужны |
| Почему клиент – поток (Thread)? | Чтобы два клиента работали одновременно и не блокировали друг друга и окно |
| Что если сервер на другом компьютере? | Достаточно указать его IP при запуске клиента: `java -jar serv.jar <IP>` |
