# ЛР2. Вопросы преподавателя и ответы

Сначала четыре «Контрольных вопроса» из методички, затем то, что преподаватель перечислила в чате («куча, стек, кэш, асинхронный ввод-вывод, три назначения буфера, сокет, класс PrintWriter, IP и порт, TCP/IP отличия»).

---

## Контрольные вопросы из методички

### 1. Назначение протоколов TCP и UDP. В чём отличие?
| | **TCP** | **UDP** |
|---|---|---|
| Соединение | устанавливается (трёхстороннее рукопожатие SYN → SYN-ACK → ACK) | нет, просто отправка датаграмм |
| Надёжность | гарантирует доставку, порядок, повтор потерянных | не гарантирует: пакет может потеряться, прийти дважды, в другом порядке |
| Скорость | медленнее (накладные расходы) | быстрее |
| Единица данных | поток байтов | датаграмма |
| Java-классы | `Socket`, `ServerSocket` | `DatagramSocket`, `DatagramPacket` |
| Где нужен | почта, веб, банк, файлы | видео, голос, игры, DNS |

В лабе используется **TCP** — счёт нельзя терять.

### 2. С помощью каких объектов и методов данные отсылаются по сети?
- Сервер: `ServerSocket server = new ServerSocket(3001)`; `Socket s = server.accept()` — ждёт клиента.
- Отправка: `PrintStream ps = new PrintStream(s.getOutputStream()); ps.println("Account:" + amount); ps.flush();`
- Приём: `DataInputStream dis = new DataInputStream(s.getInputStream()); dis.readLine()` (в нашем сервере — `BufferedReader` поверх `InputStreamReader`).
- Закрытие: `s.close()`.

`getOutputStream()` — «труба» для записи в сокет, `getInputStream()` — для чтения.

### 3. Как реализовать пересылку данных в обратном направлении (от клиента к серверу)?
Сокет **двусторонний**. Клиент берёт `s.getOutputStream()`, оборачивает в `PrintStream` и пишет `ps.println(request); ps.flush();`. Сервер читает `new BufferedReader(new InputStreamReader(s.getInputStream())).readLine()`.
В нашей программе так клиент передаёт команду **`ADD`** или **`WITHDRAW`**, а сервер по ней решает, добавлять или снимать.

### 4. Как определить сетевой адрес компьютера?
- Windows: `ipconfig` → «IPv4-адрес»; macOS/Linux: `ifconfig` / `ip a`.
- Из Java: `InetAddress.getLocalHost().getHostAddress()` или перебор `NetworkInterface.getNetworkInterfaces()`.
- В проекте: окно сервера показывает IP в заголовке (метод `localAddresses()`), плюс скрипты `show-ip.bat` / `show-ip.sh`.
- `127.0.0.1` (localhost) — «этот же компьютер».

## Вопросы из чата преподавателя

### Сокет
**Сокет** — конечная точка сетевого соединения = **IP-адрес + порт**. Клиентский `Socket(host, port)` соединяется с серверным `ServerSocket`, который слушает порт и через `accept()` создаёт сокет для каждого клиента.

### IP и порт
- **IP** — адрес компьютера в сети (кто).
- **Порт** — номер «двери» приложения на компьютере (какая программа), 0–65535. У нас **3001**.
- Пара «IP:порт» однозначно определяет, с кем соединяться.

### Отличие TCP/IP (стек протоколов) от TCP
**TCP/IP** — модель из 4 уровней: канальный → **IP** (адресация, маршрут пакетов) → **TCP/UDP** (транспорт) → прикладной (HTTP…). **IP** доставляет пакеты по адресам без гарантий, **TCP** поверх него добавляет соединение и надёжность.

### Три назначения буфера
1. Выравнивание скорости между медленным диском и быстрой ОП.
2. Асинхронный ввод-вывод.
3. Кэширование данных.
(В лабе: у `PrintStream` и `BufferedReader` есть буфер, поэтому `flush()` обязателен — он «выталкивает» накопленные данные в сеть.)

### Куча, стек, кэш
- Стек — локальные переменные и вызовы методов каждого потока.
- Куча — объекты (`new Socket`, `new Thread`), общая для потоков.
- Кэш — быстрая память процессора.

### Асинхронный ввод-вывод
Операция не блокирует программу: поток продолжает работу, а данные передаются «в фоне». В лабе каждый клиент запускается в **отдельном потоке** (`Thread`), поэтому окно не зависает во время обмена с сервером; `readLine()` внутри потока блокирует только этот поток.

### Класс `PrintWriter` / `PrintStream`
Удобные классы **текстового вывода**: `println`, `print`, `printf`. `PrintStream` пишет в байтовый поток (как у нас), `PrintWriter` — в символьный (`new PrintWriter(new OutputStreamWriter(out), true)` — автосброс буфера при `println`).

### «Потоки или процессы» (у каждого своё задание)
- **Потоки (Thread)** — внутри одной программы, делят память; обмен — через общую (глобальную/`static`) переменную. В лабе: `static int amount` в `Account` — общий счёт.
- **Процессы** — отдельные программы (отдельные проекты), общаются только через сокеты.
- Вариант 1 — два процесса без потоков; вариант 2 (наш) — потоки; вариант 3 — один клиент и два счёта.

### «На защиту брать жертву (3 компьютера)»
Нужно показать работу по сети: **компьютер 1 — сервер** (`1-start-server`), **компьютеры 2 и 3 — клиенты** (`2-start-client` + IP сервера), все в одной Wi-Fi сети; по очереди нажимать кнопки. Если не подключается — открыть порт 3001 в брандмауэре (`ADMIN-open-port-3001.bat`). Подробно — в `01-ЗАПУСК.md`.

## Вероятные вопросы по коду

| Вопрос | Ответ |
|---|---|
| Зачем `while (true)` в `Account.run`? | Сервер должен обслуживать клиентов бесконечно |
| Что делает `accept()`? | Блокируется, пока не подключится клиент, и возвращает его сокет |
| Почему `static int amount`? | Счёт общий для всех клиентов, существует в одном экземпляре |
| Зачем `flush()`? | Вытолкнуть данные из буфера в сеть, иначе клиент их не получит |
| Чем клиент 2 отличается от клиента 1? | Клиент 2 имеет только кнопку «снять» (вариант 2) |
| Что если сервер не запущен? | `new Socket` кидает исключение, `s == null`, в журнал пишется «нет связи с сервером» |
| Зачем `start()`, а не `run()`? | `start()` создаёт новый поток; `run()` выполнился бы в текущем |
